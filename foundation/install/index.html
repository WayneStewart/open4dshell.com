The installer

Foundation is a component, but parts of it have to live in your database: a small set of methods it calls, the tables some of its modules keep their data in, and the forms its windows are built on. It adds none of them without asking. The installer lists what is missing and waits for you to choose Install or Cancel.

This page shows what the installer shows, so you can read it before you open your database.

Running it

  1. Copy Foundation.4dbase into your project's Components/ folder.
  2. Open your database in 4D, in interpreted mode.
  3. Run the method Fnd_Shell_Installer. The installer also opens by itself at start-up when something is missing.
  4. Read the list, then choose Install or Cancel.

Install adds everything listed below that your database does not already have. Cancel adds nothing: your database is left untouched and you can simply remove the component. A compiled database is never changed.

After installing, restart the database so the new tables are available and the new methods compile.

When nothing is missing, the installer says so and offers only Done; the page then shows nothing else unless there are hook updates or you came from the new-release notice. If it also has changes to offer for hook methods you already have, it offers Apply and Cancel instead (see Hook methods Foundation has changed). Run Fnd_Shell_Installer at any time to see the page; Read More on it opens this page.

When a new release is installed

The first time your database opens interpreted after you put a new release of Foundation in its Components/ folder, Foundation says so and offers three answers:

  • Review now opens the installer page, which leads with what has changed in this release. Nothing is changed unless you choose Install there.
  • Skip this release asks again at the next release.
  • Never ask stops the question for this database. The installer is still there to run by hand.

The answer is kept in Settings/Foundation.json, in the database's folder beside its Project folder. Installing a release, or opening the installer when there is nothing to add, counts as an answer, so you are not asked about a release you have just installed. A compiled database, a server and a remote client never ask, so the people who use your application never see it.

The sections below follow the order of the installer's page. Each appears only when it has something to show.

Database methods

Foundation starts and quits only when your database methods call it. Add each line to its method, creating the method if you have none:

  • On Startup: Fnd_Shell_OnStartup
  • On Exit: Fnd_Shell_OnExit

This section appears whenever there is something to install. The installer never reads your database methods, so it cannot tell whether yours already call Foundation. If your database lacks either method, the installer also offers a ticked box, Start Foundation when this database opens; with it ticked, Install creates whichever of the two is missing, with its one line. A method you already have is never changed: add the line to it yourself.

Table upgrades

Listed only when one of your tables needs it. Back up before choosing Install.

Hook methods Foundation has changed

These hook methods are in your database already, and the version Foundation supplies has changed since. Nothing is written unless you tick a box and choose Apply (or Install, when other items are missing too). Your present code for each ticked method is first saved in a folder named Foundation Backups, in your database's folder. Each method is listed in one of four ways:

  • Replace: yours is as Foundation supplied it in an earlier release, so ticking it replaces it with the current version.
  • Apply Foundation's changes: you have added code, and Foundation's changes do not overlap yours, so ticking it applies them and keeps your code.
  • Overlapping changes: Foundation's changes overlap yours. There is no box; copy what you want by hand.
  • Not traceable: yours differs from the current version and Foundation cannot tell which version it began from, usually because it was written for a much earlier Foundation. There is no box; these are folded together under one line at the end, for reference only.

Show changes under each method opens the difference, so you can decide before ticking. The closing alert names the methods updated and where their backups are.

Installed earlier, since changed

These forms and pictures are in your database already and differ from the ones this Foundation carries. Nothing here is changed by Install. Superseded: Foundation has a newer version and yours is as Foundation supplied it. Edited: yours has been changed since it was installed.

To take the current version of a superseded form, delete its folder from your Forms folder and run the installer again. Keep a form marked edited.

What is never changed

Your own code in a hook method is never changed unless you tick it under Hook methods Foundation has changed, and then only after a backup. A form or picture already in your database is never changed, and neither is a database method you already have. A Foundation host method whose parameters are out of date is replaced, with the previous code kept below it as a comment.

The hook and host methods are described in chapter 4 of the Developer Guide; chapter 3, Starting fresh, covers a new database from the beginning.
