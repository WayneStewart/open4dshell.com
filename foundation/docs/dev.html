Fnd_Dev_CompilerCheck

Fnd_Dev_CompilerCheck

Runs a syntax check of your project (Compile project with no targets) and reports the result: a summary goes to the pasteboard and an alert shows it. Holding Option (Alt on Windows) while the check finishes puts the concise rather than the indented JSON on the pasteboard.

Files edited outside the 4D IDE are picked up first, so the check sees the current source.

Interpreted mode only.

No parameters.

Fnd_Dev_ConvertOnValidate

Fnd_Dev_ConvertOnValidate

Opens a window that helps you move the code your forms run on On Validate into Fnd_Hook_IO_OnValidate, so the forms can open with DIALOG. It steps through each form method, object method and project method that handles On Validate without calling the hook, one at a time, showing the method as it is and, ready to edit, the hook and the method as they would be afterwards. Nothing is written until you click Apply; the first Apply asks whether Foundation may change your database. Originals are saved in Resources/Foundation/OnValidate-Backups when that folder's parent exists.

Run it from the Execute Method dialog. Interpreted mode only, with the sources on disk.

No parameters.

Fnd_Dev_ResizeDesignWindows

Fnd_Dev_ResizeDesignWindows

Resizes any open Method, Form or Explorer windows in your database's design environment. Used to resize the windows while developing.

To use it, open the windows you want resized, switch to the User environment and select this method from the Execute dialog.

No parameters.

Fnd_Dev_SanityCheck

Fnd_Dev_SanityCheck --> Object

Sweeps your forms for what the compiler cannot see, and returns what it found: each form against 4D's forms schema, the events each form and object enables against the events its methods test, and, in table forms, what stops working when the form opens with DIALOG. Reads the sources on disk, so run it interpreted. Nothing is shown on screen.

$result_o:=Fnd_Dev_SanityCheck
$result_o.counts.error, .warning, .note; $result_o.findings[0].message

The compile-check watcher runs the same sweep on {"action": "sanity"}.

ParameterTypeDirectionDescription
ResultObjectoutfindings (collection of {check; severity ("error", "warning" or "note"); where; message}), counts ({error; warning; note}), checks (names run), forms, methods (numbers read) and ms (time taken)

Fnd_Dev_SchedStart

Fnd_Dev_SchedStart

Starts the compile-check watcher in your database. The watcher polls <Resources>/schedulerRequest.json in your database's Resources folder every 5 seconds, runs the action it names (a compile check, a test run or a relaunch), and writes the outcome to <Resources>/schedulerResult.json. Your project is the one checked.

Call it once from On Startup.

A developer tool, driven by the developer and by AI working alongside them.

Interpreted mode only. In compiled mode this is a no-op.

Stop the watcher with Fnd_Dev_SchedStop.

No parameters.

Fnd_Dev_SchedStop

Fnd_Dev_SchedStop

Asks the watcher started by Fnd_Dev_SchedStart to stop. It exits on its next 5 second tick. Calling this with no watcher running does nothing.

No parameters.

Fnd_Dev_WriteClassDocumentation

Fnd_Dev_WriteClassDocumentation

Writes Documentation/Classes/<class>.md in your database for every class in your project, so a class has a page in the Explorer's preview area the way a method does.

The page is built from what is already in the class file: the block comment at the top becomes the description; each Function line becomes a heading and a prototype; the comment lines immediately under a Function line become that function's description. Functions whose names begin with an underscore are left out. A class with no live code has no page, and any page it had is removed.

Takes no parameters and shows no alert, so it is safe to drive headlessly.

No parameters.

Fnd_Dev_WriteDocumentation

Fnd_Dev_WriteDocumentation {($options_o : Object)}

Writes documentation comments for your project's methods, into your database's Documentation/Methods folder. It assumes your method header comments are formatted the way Foundation's are.

$options_o is optional; any property left out takes the default shown: methodName     - "" or omitted: all methods; a prefix (Eg. Inv_); or one specific method name tooltip        - default True. True writes the leading <!-- --> block into each method's comments; False strips it from every method it touches excludePrivate - default False. True: exclude Private methods and shared aaa methods silent         - default False. True: don't show a final "Finished" alert inline         - default False. True: run in the calling process rather than spawning one. Use in headless/CI contexts

Fnd_Dev_WriteDocumentation({methodName: "Inv_"; silent: True})

ParameterTypeDirectionDescription
optionsObjectinOptions, as described above (optional)
