4. Hooks and host methods

A hook is a method in your database that Foundation calls at a defined moment, by name, with EXECUTE METHOD. If the method is absent Foundation does something sensible. If present, it must be shared (the "Shared by components and host database" attribute), or the call fails. Foundation creates each hook it needs on first startup in an interpreted host, with the expected parameters and a comment saying what it is for, so the easiest way to get one is to let Foundation make it and then fill it in. Foundation Product Sales has a working copy of every one.

A host method (Fnd_Host_*) is the same mechanism used the other way: a small method Foundation needs you to have because a component cannot do the thing itself. Foundation creates these too and you normally never edit them.

When a hook's signature changes

Foundation compares an existing hook's declared parameters with the ones it now passes (interpreted hosts only) and reports a mismatch at startup rather than rewriting your code. Release/UPGRADING.md lists every such change by release.
