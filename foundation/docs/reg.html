Fnd_Reg_CreateTable

Fnd_Reg_CreateTable --> Object

Creates the [Fnd_Reg] table the Registration component needs, in an interpreted host. Fnd_Reg_Init offers to call it; a developer can also call it directly. If the table already exists, nothing is changed.

The table it creates: ID               Longint, primary key Feature_Code     Alpha 80 (Fnd_Reg_Init indexes it) Demo_Days        Integer Demo_Start_Date  Date Unlock_Code      Alpha 40 User_Name        Alpha 80 License_Info     Alpha 80 Checksum         Alpha 40

In a compiled host, or on a remote client, it changes nothing and returns success False with a message. After it creates the table, restart the host before using Fnd_Reg.

ParameterTypeDirectionDescription
ResultObjectout{ success : Boolean ; created : Boolean ; restartRequired : Boolean ; message : Text }

Fnd_Reg_DemoMessage

Fnd_Reg_DemoMessage ({feature code{; message}}) --> Text

Sets and gets the demo message for the specified feature code.

This text is displayed in the demo dialog.

This text can be localized, so it's not stored in the with the registration record. If you want to use something other than the default values, you'll need to call this method to set up the names before trying to retrieve them or before displaying the registration dialogs.

Pass an empty string to revert to the default message (from the localization strings).

ParameterTypeDirectionDescription
inFeatureCodeTextinThe feature code (optional)
inMessageTextinThe new demo message (optional)
ResultTextoutThe current demo message

Fnd_Reg_FeatureName

Fnd_Reg_FeatureName ({feature code{; feature name}}) --> Text

Sets and gets the feature name for the specified feature code.

This name is used in the registration dialogs.

These names can be localized, so they're not stored in the with the registration information. If you want to use something other than the default values, you'll need to call this method to set up the names before trying to retrieve them or before displaying the registration dialogs.

The Application code returns the database name.

Other feature codes return "Feature: codename"

ParameterTypeDirectionDescription
inFeatureCodeTextinThe feature code (optional)
inFeatureNameTextinThe new feature name (optional)
ResultTextoutThe current feature name

Fnd_Reg_GetExpirationDate

Fnd_Reg_GetExpirationDate ({feature code}) --> Date

Gets the feature's expiration date. This is calculated by adding the number of demo days to the date the demo period was started.

If the demo hasn't been started, the number of demo days is added to the current date, and the resulting date is returned.

ParameterTypeDirectionDescription
inFeatureCodeTextinThe feature code (optional)
ResultDateoutThe expiration date

Fnd_Reg_Info

Fnd_Reg_Info (label) --> Text

Returns requested information. See the Fnd_Gen_ComponentInfo method for more information.

Fnd_Reg licenses the host developer's application, not Foundation: it shows the host's demo and registration dialogs and checks the unlock codes the host issues.

Fnd_Reg needs a [Fnd_Reg] table in the host: ID Longint, Feature_Code Alpha 80, Demo_Days Integer, Demo_Start_Date Date, Unlock_Code Alpha 40, User_Name Alpha 80, License_Info Alpha 80 and Checksum Alpha 40. Fnd_Reg_Init offers to create it with Fnd_Reg_CreateTable.

ParameterTypeDirectionDescription
requestTextinInfo desired ("version" or "name")
ResultTextoutResponse

Fnd_Reg_SetSecretKey

Fnd_Reg_SetSecretKey (key)

Allows the developer to set the secret key.

For security reasons, there is no routine to get the secret key.

Fnd_Reg licenses the host developer's application, not Foundation: it shows the host's demo and registration dialogs and checks the unlock codes the host issues.

Security: Fnd_RegG_GenerateUnlockCode ships in Foundation's source, so a host must set its own key with Fnd_Reg_SetSecretKey at startup. The MD5-based codes deter casual copying only; they are not copy protection.

ParameterTypeDirectionDescription
keyTextinThe secret key
