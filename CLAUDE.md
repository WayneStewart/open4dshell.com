# open4dshell.com — agent guide

Static site for Open 4D Shell, Wayne Stewart's home for open-source 4D
components. This repository is **public**. Nothing private goes in it:
no signed documents, no correspondence, no credentials, no details of
Foundation's history beyond what `foundation/PROVENANCE.md` states.

Read `README.md` first for layout and the docs refresh procedure. This file
adds what an agent needs to work here safely.

## Working rules

- Australian spelling: licence, organisation, colour, behaviour.
- Plain semantic HTML5, one stylesheet per folder, no frameworks, no
  CDNs, no external fonts. Light and dark via `prefers-color-scheme`.
  Understated tone, no marketing copy.
- No JavaScript anywhere. Every page, including the generated reference
  under `foundation/docs/`, must read and navigate fully without it;
  search in the reference is the browser's find on `docs/all.html`.
- Contact address everywhere is `wayne.b.stewart@gmail.com` (deliberate,
  2026-11-01: the `wayne@open4dshell.com` mailbox is not yet connected). It
  appears in the footer of every hand-written page and in the docs frame
  generated by `scripts/build-docs.mjs`; change all of them together.
- Never hand-edit the generated files under `foundation/docs/`. They are
  built here by `scripts/build-docs.mjs` from the method documentation in
  the Foundation repository (f6); fix the source there (usually the method
  header, which 4D exports to `Documentation/Methods/`) and rebuild. The
  exceptions are `foundation/docs/docs.css` and `foundation/docs/original/`,
  which are hand-maintained and which the generator leaves alone.
- `foundation/LICENSE` and `foundation/PROVENANCE.md` are verbatim copies of
  the Foundation repository's root `LICENSE` and `PROVENANCE.md`. Change
  them there first, then copy them across by hand.
- Commit with `git add -A`; keep the tree clean. Pushing to `main` deploys.

## Hosting

Cloudflare account (Wayne's), zone `open4dshell.com`, DNS on Cloudflare,
registrar Hover. Two Cloudflare Pages projects connected to this GitHub
repository, production branch `main`, no build command:

| Pages project | Root directory | Hostname |
|---|---|---|
| `open4dshell-www` | `www` | www.open4dshell.com, and the apex |
| `open4dshell-foundation` | `foundation` | foundation.open4dshell.com |

Every push to `main` redeploys both within about a minute; there is
nothing to trigger. Pages serves clean URLs (`/docs/history` for
`/docs/history.html`) with a 308; that is default behaviour, not a bug.
Cloudflare's Email Address Obfuscation rewrites `mailto:` links in the
served HTML; the source stays plain.

A new subdomain = a new top-level folder here + a new Pages project with
that folder as root directory + a custom domain on the project.

A smaller project needs none of that: a folder under `www/` (for
example `www/kvp/`) is served at `www.open4dshell.com/kvp/` on the next
push. Promote to a subdomain later only if the project grows its own
docs and identity.

## Verifying a deploy

```bash
for h in www.open4dshell.com foundation.open4dshell.com open4dshell.com; do
  curl -sS -o /dev/null -w "%{http_code} %{url_effective}\n" -L "https://$h/"
done
```

## Relationship to Foundation

The Foundation source lives in a separate, private repository (`f6`, on
Bitbucket). Foundation work, its Jira tickets (FND project) and its
release never happen from this repository. This site only publishes
copies. Foundation's own history is in `foundation/docs/history.html`;
the authoritative source for it is `Documentation/Foundation-History.json`
in the Foundation repository.

Foundation 6.0.0-beta.1 opened as a private beta on 1 November 2026. The
beta snapshot and its GitHub Releases live in
`github.com/open4dshell/Foundation-Shell` (private until 1 December 2026,
public from then); the demo database is public at
`github.com/open4dshell/Foundation-Product-Sales`. The site links to
both; it hosts no builds and no checksums.

The Developer Reference (`foundation/docs/`) is generated in this
repository by `node scripts/build-docs.mjs /path/to/f6`, which reads
`Documentation/Methods/*.md`, `Documentation/Classes/*.md` and
`Documentation/Foundation-History.json` and never writes to f6. Only
methods whose Attributes line says Shared are published, one page per
`Fnd_<Module>_` prefix. The built component carries no documentation (a
large bundle of HTML files made code signing hang); it opens this site
instead, so page names and method anchors (`/docs/pref.html#Fnd_Pref_GetText`)
are a public interface and should stay stable. The generator lists the
source files it could not parse; those are fixed in f6's method headers,
never here. The earlier reference, built from a PDF extraction, is
retired; the Foundation 5.4 manual stays at
`foundation/docs/original/Fnd_5.4_Docs.pdf`. This site is to grow into the
learning resource for Foundation, and that design is still open.
