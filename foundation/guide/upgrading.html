Foundation — upgrade notes for host databases

Written 2026-08-13 for the host developer, not the Foundation developer. The companion to README.md: that document says how a release is cut, this one says what a host must do to accept it.

One section per release, newest first. Every entry answers three things — what changed, what the host sees, what the host must do. An entry that needs no action still belongs here, because "we checked and it is safe" is worth recording once rather than re-deriving per site.

What counts as a breaking change

Foundation's contract with a host is every method carrying "shared":true, at the signature it had when the host was written. Not the methods a header comment calls public — hosts invoke Foundation by name at runtime through EXECUTE METHOD, stored method names and object-method wiring, and none of that is visible to any static reading of the component.

That distinction is not theoretical. In March 2026 the surface was narrowed from 697 to 451 shared methods on the strength of Access: header comments, shipped as Foundation 20 LTS, and broke host databases in the field. The rule since: a shared method is contract until runtime evidence from real hosts says otherwise, and removal is staged deprecation, never a flag flip.

So the categories below are ordered by what they cost a host:

  • Breaking — a call that compiles today stops working. The host must act.
  • Behavioural — the call still works and returns a different answer. The host must decide whether it cares.
  • Additive — new capability. Nothing to do.

6.0.0-beta.1 (private beta, 1 November 2026)

First release under the new versioning scheme. The component is built for four targets from one commit, all carrying the same version: 20L (4D 20 LTS), 20R (4D 20 R), 21L (4D 21 LTS) and 21R (4D 21 R). The floor is 4D 20 LTS; 4D 19 is no longer supported. Foundation is released under the MIT licence.

Breaking

Foundation's own licensing is gone. Fnd_Gen_Reg_*, Fnd_Gen_RemoveActivationCode, their two forms and Resources/Fnd_License.xml are removed (FND-61, FND-62). A host that called Fnd_Gen_RemoveActivationCode, or had a menu item for it, must remove the call. Fnd_Reg, which licenses the host's application, is unaffected.

cs.fnd.wnd is no longer published. The unfinished class is now _wnd_sketch. A host that referred to cs.fnd.wnd must remove the reference; nothing worked through it (FND-44).

The standalone Logging component is removed, and Foundation records through Fnd_Log (FND-96). A host that installed Logging.4dbase only for Foundation's sake can remove it; a host that calls the Logging component's own methods keeps its copy.

German's language code is DE, not GR. Fnd_Loc_LanguageCode returns DE. A host with its own _GR lists for German renames them _DE.

Behavioural

Fnd_Reg offers to create [Fnd_Reg]. A host that uses Fnd_Reg without a [Fnd_Reg] table no longer aborts. In an interpreted host during development, Fnd_Reg asks whether to create the table, then asks for a restart; a compiled host gets a report. Either way Fnd_Reg stays inactive for the session. Hosts with the table already in place need do nothing (FND-85). Fnd_Reg_Init is not part of the published API: do not call it from a host.

Fnd_Reg registration fixes (FND-87, FND-90, FND-93, FND-94). Duplicate records are resolved rather than aborting; days remaining honour a demo period set before the demo starts; the registration dialog is not shown once registered; and a tampered record reports Expired on the call that detects it. Hosts need do nothing.

Fnd_Loc names a missing Fnd_Host_ListToArray. A host without the hook now gets one report naming it, instead of empty strings (FND-39). Hosts that have the hook see no change.

Fnd_Dlg keeps its state in objects. The module's process and interprocess variables (Fnd_Dlg_Text1_t, <>Fnd_Dlg_ProgFrom_i and the rest) are gone, replaced by Fnd.Dlg and Storage.Fnd.Dlg. Component variables were never visible to a host, so the public methods behave as before, with one exception: Fnd_Dlg_SetIcon(0), or any value other than Fnd_Dlg_WarnIcon and Fnd_Dlg_StopIcon, now resets the next alert to the Note icon instead of leaving the previous alert's icon in place. A host that wants the old leak has none.

Development history in method headers is one line. Every modification line dated 2026-08-01 to 2026-11-01 reads "Prepare Foundation 6 release"; earlier lines are unchanged. Nothing to do; it is why a diff against Foundation 5 headers looks shorter than the code change.

Additive

  • Fnd_Reg_CreateTable is new and shared, for creating the [Fnd_Reg] table by hand in an interpreted host.
  • Fnd_Art_VersionHistory is new. A host can pass release notes (styled text, newest first) to show on the About box's About tab; without them the area is hidden. The generic About box is now tabbed (About / Foundation / Foundation Licence), resizable, and credits Dave Batton and Walt Nelson (FND-59).
  • Fnd_VS_zProbeHostLists is published, as a diagnostic: it reports which route to a host's choice lists works in that database.

Also in 6.0.0-beta.1 — the August 2026 modernisation of Fnd_Text and Fnd_Data

The Fnd_Text and Fnd_Data modules were modernised: hand-written MD5 and Base64 replaced by the 4D commands that now do the same work, and module state moved out of interprocess variables into Storage.

Breaking

63 methods are no longer callable from a host. They carried "shared":true and no longer do — 33 Compiler_Fnd_* methods and 30 Fnd_*_Init methods, including Fnd_Init itself. The shared surface went from 698 to 633.

This is deliberate and settled (Wayne, 2026-08-13). Neither family is part of the published API: Compiler_Fnd_* methods are declaration scaffolding a host has no reason to name, and Fnd_*_Init is called by every public method in its module on entry — and has been since 2004 — so a host calling one was calling it a second time for no effect.

Note that the change is not merely documentary. The %attributes flag is what 4D checks when a host resolves a name, so the same edit that corrected the claim also withdrew the method.

A host that calls any Fnd_*_Init directly will therefore fail at that call. This is not hypothetical: Foundation-Product-Sales, the reference host, calls Fnd_Wnd_Init from a form object method (Forms/_Matrix_Testing/ObjectMethods/Button.4dm, line 1).

What to do. Nothing, if the host only calls public Fnd_<Module>_<Verb> methods — every one of those kept its flag, verified method by method. If the host calls an Init or a Compiler_Fnd_* method directly, delete the call rather than replacing it; there is nothing to replace it with, and nothing was relying on it.

Three MD5 helpers were removed, having been shared:true: Fnd_Text_TextToMD5_Bits32Add, Fnd_Text_TextToMD5_Bits32Left, Fnd_Text_TextToMD5_Calc. They were the internals of the hand-written digest and are meaningless outside it. A host calling them was reaching into the implementation; use Fnd_Text_TextToMD5.

Interprocess and process variables are gone, not renamed. A host reading any of these by name finds nothing:

WasNow
<>Fnd_Data_Initialized_bStorage.Fnd.Data.Initialized
<>Fnd_Data_NameTitles_atStorage.Fnd.Data.nameTitles (collection)
<>Fnd_Data_UserBypassKey_iStorage.Fnd.Data.bypassKey
Fnd_Data_FormatError_iFnd.Data.formatError (per-process object)
<>Fnd_Text_Initialized_bStorage.Fnd.Text.Initialized
<>Fnd_Text_CapExcludeWords_atStorage.Fnd.Text.capExcludeWords (collection)
<>Fnd_Text_Text2MD5_SINUS_airemoved — the sine table of the digest it served
Fnd_Text_TempBlob_blobremoved — the Base64 methods use a local blob

Prefer the accessor to the storage location in every case: Fnd_Data_FormatError rather than reading Fnd.Data.formatError, Fnd_Text_CapitalizeExclude rather than touching the collection. The accessors are shared and stable; the layout behind them is not contract.

Two flags were re-spelled to the US spelling the rest of the component uses. <>Fnd_Tbl_Initialised_b is now <>Fnd_Tbl_Initialized_b, and the per-process Fnd.List.Initialised is now Fnd.List.Initialized. This matters beyond tidiness: Fnd_Gen_Reset builds the flag name as a formula and swallows the error when it misses, so a module spelling its own flag the British way was silently never reset.

Behavioural

Fnd_Data_FormatWebURL now defaults to https. A URL arriving with no scheme was given http://; it is now given https://. Trailing-slash normalisation, which previously matched only http://, now applies to both. A URL that already carries a scheme is untouched, as before.

Fnd_Data_FormatWebURL("example.com")                    // https://example.com/
Fnd_Data_FormatWebURL("example.com"; {scheme: "http"})  // http://example.com/

Stored values are not migrated. A host that formatted URLs on entry has http:// in its data and will produce https:// from now on, so the same input will not match a stored value. Pass {scheme: "http"} to keep the old behaviour at a particular call site.

Fnd_Text_EncodeBase64Blob no longer prefixes a carriage return. The old encoder wrote a line break before the first character and sized the blob to allow for it, so Fnd_Text_TextToBase64("Man") returned five characters where four were asked for. It now returns TWFu.

This reaches Fnd_Text_TextToBase64 too, and it changes the output every existing caller has been receiving. Anything that stored, transmitted or compared those values holds strings with a leading carriage return that fresh encodings will no longer match. The 76-character wrapping is unchanged — BASE64 ENCODE does not wrap, so the wrapper still does.

Verified unchanged

Recorded because they are the changes most likely to be feared:

  • MD5 digests are identical. Fnd_Text_TextToMD5 delegates to Generate digest, and the default charset stays ISO-8859-1 — what the hand-written digest always used — so stored digests still match. Test_Fnd_Text asserts the RFC 1321 vectors and the accented-text digest against the default.
  • Base64 decoding still tolerates whitespace. The old decoder ignored line breaks incidentally; BASE64 DECODE is stricter, so Fnd_Text_DecodeBase64Blob now strips CR, LF, tab and space before calling it. Same result, deliberately.
  • Fnd_Text_Wrap output is unchanged. Rewritten to walk an index rather than delete the front of the text on each pass — a performance change only, pinned by boundary tests including exactly-at-limit, over-limit with no space, and an embedded carriage return.

Additive

  • cs.fnd.text — the Fnd_Text module through the class store: cs.fnd.text.new().capitalize("hello world"). Every function delegates to the method of the same behaviour, so the two routes cannot diverge. 4D 20 LTS has no singletons, hence new().
  • Fnd_Text_MD5Encoding — reads the default MD5 charset, or sets it for every later call.
  • New trailing optional parameters, all backwards compatible: Fnd_Data_FormatWebURL and Fnd_Data_FormatText take an options object; Fnd_Data_EmailAddressError takes a pointer for the description; Fnd_Text_TextToMD5 takes a charset.
  • Fnd_Data_FormatPhone and Fnd_Data_FormatPostalCode widened their style parameter from Integer to Variant and dispatch on Value type, so an options object is accepted where the legacy style constant still works.
  • Fnd_Data_ParseName now also returns an object, in addition to the output pointers it has always filled.
